## Accomplished

Repair session for PR #7920 ("meditate: agent-worker-flow Step 2 tells agents to
reset --hard without checking for uncommitted work", closes #7917). The PR was
`CONFLICTING` against `main`; both CI checks were already green.

**Diagnosis.** One conflict, in `.claude/skills/agent-worker-flow/SKILL.md`. Both
sides had edited the same Step 2 material for the same reason and arrived at
different shapes:

- The PR restructured Step 2 into an ordered `2a` (snapshot) / `2b` (skill
  staleness) / `2c` (branch), collapsing three verbatim-duplicated guard blocks
  that had accumulated by append.
- `main` had meanwhile (#7873/#7875) added a top-of-file Step 0 plus new prose
  *inside* the old flat Step 2 — i.e. into the very blocks the PR deleted.

So git could not auto-merge: deleted-and-restructured on one side, modified in
place on the other. Main's Step 0 and its other additions (the dependency-PR
merge sweep, the read-issue-comments block) merged cleanly on their own.

**Resolution.** Kept the PR's 2a/2b/2c structure and grafted main's substantive
additions into the corresponding sub-step, rather than taking either side whole:

- into 2a: the `coordination create-pr` rationale (leftover edits are not inert —
  create-pr stages the whole worktree and `.claude/` edits get the PR rejected);
  the "insertions are older wordings of lines that still exist" staleness tell;
  and main's incident log, reconciled with the PR's. The two sides listed
  overlapping-but-different deletion counts, so the merged parenthetical carries
  the union (169, 279, 294, 320, 364).
- into 2a: main's **"keep that cross-file duplication"** point, reworded to say
  *cross-file*. This was the one place the two sides genuinely pulled against
  each other. It is not actually a conflict: the PR collapsed duplication *within*
  `SKILL.md`, whereas the point main is making is about the copy of the check in
  `.claude/commands/{work,feature}.md`, which no side touched and which is the
  only copy that can fire when `SKILL.md` itself is the stale file.
- into 2b: main's data point that restoring the file is not sufficient on its own
  (the 318-vs-539 session saw the Step 7 rules only because it restarted from
  Step 1 after restoring).
- deleted the leftover duplicate staleness block that the PR had collapsed and
  main had edited in place; its content is fully covered by 2b.

Verified nothing from main was silently dropped by diffing the merged file
against `origin/main` and accounting for every removed line as either relocated
into 2a/2b/2c or part of the intentionally collapsed duplicate.

The issue's acceptance criterion still holds after the merge: `grep -rn "reset
--hard\|checkout -- \.\|clean -fd" .claude/` returns hits only in
`agent-worker-flow/SKILL.md`, each either the section's own meta-statement or
explicitly predicated on the 2a snapshot.

**This session was itself another instance of the bug** — the third consecutive
one recorded on this PR. The worktree arrived with 567 deletions across six
`.claude/` files and nothing added, which would have reverted both the skill and
all five command files. Snapshotted to `/tmp/622823d2-d3c2-407f-be23-660f85905610-stale.patch`
and parked at `stash@{0}` ("pod 622823d2-... pre-repair"); nothing was discarded.
Worth recording: `git stash list` in this worktree now holds **116** stashes,
nearly all of them prior sessions setting aside this same accidental revert. That
is the strongest evidence yet that the PR is fixing a real and recurring failure,
and it is why the merged 2a keeps the incident log rather than trimming it as
redundant prose.
