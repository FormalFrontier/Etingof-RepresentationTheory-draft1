The existing `hooke_law` takes `f : End(V) →ₗ[ℝ] End(V)`, a strictly stronger hypothesis than
the book's data, so it could not be instantiated at an elasticity law. New declarations:

* `conjRep_symSub_mem` and `symRep : Representation ℝ SO3 symSub` — `S²V` as a genuine
  `SO(3)`-representation (the restriction of `conjRep`, via `LinearMap.restrict`).
* `symSub_subtype_equivariant` — the inclusion `S²V ↪ End(V)` satisfies the equivariance
  hypothesis, so the hypothesis is not vacuous.
* `symProj : M ↦ (1/2) • (M + Mᵀ)` with `symProj_mem`, `symProj_equivariant`,
  `symProj_eq_self`, and the codomain-restricted `symProjTo : End(V) →ₗ[ℝ] symSub`
  (`symProjTo_equivariant`).
* `symExtend f = f ∘ symProjTo` — the extension of the book's `f` to all of `End(V)`. This is
  exactly "extend by `0` on the skew summand": `symProj` kills `Λ²V` and is the identity on
  `S²V`. `symExtend_equivariant` proves the extension stays equivariant, which is the whole
  content of the reduction.
* `hooke_law_symSub` — the headline. For `f : symSub →ₗ[ℝ] End(V)` with
  `f.comp (symRep A) = (conjRep A).comp f`, there are `K μ : ℝ` with `f = K` on `ℝ·1`,
  `f = μ` on `W`, and `f x ∈ symSub` (so the stress tensor `S_P` is symmetric). Proved by
  applying the existing `hooke_law` to `symExtend f` and restricting back via
  `symExtend_apply_coe`.
* `hooke_law_symSub_add` — the book's displayed `f (x + y) = K x + μ y` on the exact domain.
* `hooke_law_symSub_two_moduli` — the actual point of the problem ("54 parameters reduce to
  2"): *every* `d : S²V` splits as `x + y` with `x ∈ ℝ·1`, `y ∈ W` (via the existing
  `symSub_eq_scalar_sup_tracelessSym`), and `f d = K x + μ y`.
* `hooke_law_add` — the same displayed form for the retained `End(V)`-domain `hooke_law`,
  which the audit noted was a one-line corollary that was simply never stated.

`hooke_law` itself is unchanged, as the issue required.
