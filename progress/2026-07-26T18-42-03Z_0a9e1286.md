## Accomplished

Meditate session on #7927: made the lint-clean policy a build check.

- `scripts/check_lint_clean.py` parses warnings out of a `lake build` log and
  ratchets them against `scripts/lint-warning-baseline.txt`.
- `.github/workflows/lean.yml` gained a "No new build warnings" step. The build
  step now writes its module list and tees its log so the check reads them
  instead of paying for a second build; it also gained `set -o pipefail`, without
  which the `tee` would have swallowed build failures.
- `.claude/skills/lean-formalization/SKILL.md` no longer claims warnings pass CI.

**Measurement (deliverable 2).** 270 of the 750 built files emit warnings, 3232
in total. A repo-wide zero-warnings check would reject 36% of the tree, which is
why the baseline exists. The dominant kinds: unused `simp` argument (560),
`linter.style.show` (537), deprecated `push_neg` (250), >100-char lines (210),
`unusedSectionVars` (140).

**Baseline design.** The issue offered "build `main` for comparison" or "require
touched files to be warning-free". Neither was taken: comparison doubles a
two-hour CI job, and touched-files-only lets warnings in untouched files
accumulate forever. The checked-in baseline is strictly stronger than both and
needs no base-ref build. Two failure conditions, so it can only shrink:

1. a file emits a warning and is not on the baseline (new warning), and
2. a baseline file was built and emitted nothing (stale entry, delete the line).

Condition 2 is restricted to files in the run's module list, so entries for
CI-excluded modules are never wrongly flagged. `Chapter5/Proposition5_22_2.lean`
is the one baseline entry outside that list; it builds locally as a dependency
but is excluded from CI's explicit targets, and is safe in both directions.

## Current frontier

Verified end-to-end locally with the exact workflow commands, not just the script
in isolation: with a scratch file carrying an unused included section variable,
`lake build` exited 0 and the new step exited 1 naming the file; with the scratch
file removed, the step passed. Both synthetic failure modes (missing entry, stale
entry) were also exercised against the real inventory log. The scratch file and
its olean were removed; `git status` is clean apart from the intended diff.

Two facts about this toolchain worth keeping:

- Lake **does** replay cached warnings for up-to-date modules (`⚠ Replayed …`),
  so a warm build reproduces the full inventory. Modules that print no line at
  all are up-to-date *and* clean, which is why 210 of 750 modules had no
  Built/Replayed line while every warning-bearing file had one.
- `lake env lean` drops the lakefile's `[leanOptions]`, including
  `weak.linter.mathlibStandardSet`, so linters do not fire under it at all. Pass
  `-D linter.mathlibStandardSet=true` (plus `maxSynthPendingDepth=3` and
  `backward.isDefEq.respectTransparency=false`) if you ever want single-file
  warning output without a build.
