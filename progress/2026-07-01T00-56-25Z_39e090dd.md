## Accomplished

Formalized issue #5740 (foundational sub-issue of #5638): a genuine monomial `Module.Basis` of
the symmetric power `SⁿV = SymmetricPower k (Fin n) V`, absent from Mathlib.

New file `EtingofRepresentationTheory/Chapter5/SymmetricPowerBasis.lean` (namespace
`Etingof.SymmetricPowerBasis`), built for an arbitrary basis `b : Basis κ k V`:

- `monomialSetoid n κ` / `Monomial n κ`: degree-`n` monomials = index tuples `Fin n → κ` up to
  permutation (`q = p ∘ σ`). No finiteness/decidability assumptions on `κ`.
- `tensorBasis b`: the `Basis.piTensorProduct` basis of `⨂ⁿV`, `p ↦ ⨂ₜ i, b (p i)`.
- `symEquiv b : SⁿV ≃ₗ[k] (Monomial n κ →₀ k)`: the symmetrized-orbit coordinate isomorphism. Forward
  map descends `Finsupp.lmapDomain (quotient map) ∘ tensorBasis.repr` through the permutation
  `AddCon` (well-defined via `toFinsuppAux_reindex`, checked on the tensor basis); inverse is
  `Finsupp.linearCombination` of `⟦p⟧ ↦ mk (tensorBasis b p)`. Both composites verified on spanning
  sets (tensor basis / `Finsupp.basisSingleOne`).
- `symmetricPowerMonomialBasis b : Basis (Monomial n κ) k SⁿV := Basis.ofRepr (symEquiv b)`, with
  `symmetricPowerMonomialBasis_toMonomial : basis ⟦p⟧ = mk (⨂ₜ i, b (p i))` — the exact form the
  `DiagonalCoordinate` criterion consumes.

No `sorry`, no `native_decide`, no `def` bodies sorried. Added the import to `Chapter5.lean`.
`lake build EtingofRepresentationTheory.Chapter5.SymmetricPowerBasis` and the full `Chapter5`
aggregation build both succeed with zero errors and zero warnings on the new file.
