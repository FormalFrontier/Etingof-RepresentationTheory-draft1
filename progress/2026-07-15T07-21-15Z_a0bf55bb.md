## Accomplished

Proved `Etingof.Problem6_1_6.mckay_connected` (issue #6651, Problem 6.1.6 part (b))
sorry-free. `#print axioms` shows only `[propext, Classical.choice, Quot.sound]` — no
`sorryAx`. Everything stays in `Chapter6/Problem6_1_6.lean`; no new imports.

The proof has two halves:

1. **McKay-path infrastructure.** `McKayAdj`/`McKayJoined` (a walk in the McKay graph via
   `List.IsChain`) with `McKayJoined.refl`/`.edge`/`.trans`/`.symm`. `.symm` uses part (a)
   `mult_symm` (edges reverse because `rᵢⱼ = rⱼᵢ`); `.trans` splices two walks at the shared
   vertex. The goal's `path.get`/`head?`/`getLast?` shape is recovered from `IsChain` via
   `List.isChain_iff_getElem`.

2. **Analytic core (character-level).** A scalar `occ n a = ⅟|G| ∑_g χ_V(g)ⁿ χ_{Wₐ}(g⁻¹)`
   (the multiplicity of `Wₐ` in `V^{⊗n}`) with:
   - recurrence `occ (n+1) a = ∑ⱼ rₐⱼ · occ n j` (from `char_eq_sum_mult` on `V ⊗ Wₐ`,
     `charV_inv`, `mult_symm`);
   - base `occ 0 a ≠ 0 → a = i₀` (the trivial vertex, via Schur `finrank_hom_simple_simple`);
   - reachability `occ n a ≠ 0 → McKayJoined i₀ a` by induction on `n`;
   - seed `∀ a, ∃ n, occ n a ≠ 0` by the faithfulness/polynomial argument of Problem 4.12.10.

   The seed needs the SU(2)-rigidity lemma `taut_char_eq_two_imp_one` (`χ_V(g) = 2 → g = 1`),
   also proved here from the existing `charV_re_le_two` matrix machinery.

### Note on "use Problem 4.12.10"

The issue suggests invoking `Etingof.Problem4_12_10` directly. That statement's hypothesis is
`IsSimpleModule k[G] σ.asModule`, but the irreducibles here are given as *categorically*
`Simple` FDRep objects (`IsCompleteIrreps.simple`). No `Simple (FDRep) → IsSimpleModule` bridge
is available in Mathlib or this repo (the categorical equivalence `Rep ≌ ModuleCat k[G]` exists
but the simple-object transfer is not wired up). Rather than build that bridge, I inlined
4.12.10's own faithfulness+polynomial argument specialized to the tautological SU(2)
representation — the same mathematics, using the character tools already in the file. A future
cleanup could add the `Simple → IsSimpleModule` bridge and call 4.12.10 directly.
