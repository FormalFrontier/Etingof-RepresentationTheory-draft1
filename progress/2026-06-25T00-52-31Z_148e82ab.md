## Key decisions

- **Opposite absorbed into a contravariant `pathMap`, not into the algebra/module side.** The
  source-to-target product `single⟨a,b,p⟩·single⟨b,d,q⟩ = single⟨a,d,p.comp q⟩` would make the naive
  path action an anti-homomorphism. Reading `pathMap` contravariantly
  (`pathMap (cons p e) = pathMap p ∘ R(eᵒᵖ)`) yields `pathMap (p.comp q) = pathMap p ∘ pathMap q`,
  so the action is a genuine **left** module map. Input is `QuiverRepresentation k Qᵒᵖ`, matching
  `forwardRep`'s output type so forward/reverse compose into a bijection (deliverable 4).
- **`Quiver.Path.rec` term-mode `pathMap`** rather than equation-compiler syntax: the latter does
  not reduce definitionally, so the `pathMap_nil`/`pathMap_cons` `rfl` lemmas failed. The recursor
  form makes both equations `rfl`.
- **`toEnd` (the algebra hom) is the constructed object**, satisfying "Definitions Must Be
  Constructed". `reverseModule` is the standard `Module.compHom` realization on top.
- **Split deliverable 4 into a follow-up issue** rather than attempting the mutual-inverse /
  iso-class bijection in this one-shot. The issue itself recommended landing (3) first.
