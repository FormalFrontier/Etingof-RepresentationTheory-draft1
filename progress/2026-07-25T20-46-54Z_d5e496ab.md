## Decisions and patterns

**Hypothesis is `(n.factorial : k) ≠ 0`, not `[CharZero k]`.** Strictly more general (it also
covers characteristic `p > n`), and it matches the existing idiom of the sibling file, which
carries `h2 : (2 : k) ≠ 0` rather than a characteristic assumption.
`factorial_cast_ne_zero k n` supplies it from `CharZero k`, and the two `…OfCharZero`
definitions package that so a char-0 user needs no argument.

**The whole argument stays inside `PiTensorProduct`.** No `ExteriorAlgebra`, so the coercion gap
recorded in `lean-formalization`'s Known Dead-Ends never comes up. The issue was right that
`Submodule.quotientEquivOfIsCompl`/`quotKerEquivRange` "applies directly" in principle, but
building the equivalence by hand from `Submodule.liftQ` + `LinearMap.codRestrict` was easier than
transporting along two submodule equalities, and it makes the compatibility lemmas `rfl`.

**The two kernel computations both reduce to one algebraic identity.** For the symmetric side,
`T - sym T = (n!)⁻¹ ∑_σ (T - σ T)`, and each `T - σ T` is in `symRelSubmodule` by
`swap_induction_on`: for `σ = s τ`, split as `(T - τ T) + (τ T - s (τ T))` — the second summand is
a *generator* with `τ T` in the generator's role. Crucially this avoids conjugating `s` by `τ`
(no `swap (σ i) (σ j)` bookkeeping and no need for `Equiv.mul_swap_eq_swap_mul`).
The exterior side is the same shape: `T - sgn(σ) σ T ∈ extRelSubmodule` via
`(T - U) + (U + s U)` with `U = sgn(τ) τ T`, and `U + s U` is fixed by `s`, hence a generator.
That is the whole reason `extRelSubmodule`'s odd-looking "fixed by *some* transposition"
definition is the right one.

**The one place characteristic 2 is genuinely needed.** `extRelSubmodule ≤ ker antisymmetrizer`
is proved by reindexing `σ ↦ σ s`, which gives `S = -S` for the signed sum, so `2 S = 0`. A
transposition exists in the generator, so `2 ≤ n`, so `2 ∣ n !`, so `(n! : k) ≠ 0` already forces
`(2 : k) ≠ 0` — no extra hypothesis needed
(`two_ne_zero_of_factorial_cast_ne_zero`, `two_le_of_ne`).

## Elaboration traps hit

* **`n !` does not parse in this project.** Mathlib's factorial notation is `scoped` in `Nat`, and
  its own docstring warns that `n !` is confusable with prefix `!`. Without `open scoped Nat` you
  get `unexpected token '!'`, and the reported error column points at the *token after* the `!`,
  which reads like a problem with the type ascription rather than the notation. The repo already
  writes `Nat.factorial n` / `n.factorial` everywhere; do that.
* **`(V := V)` again**, exactly as recorded for `exteriorPowerEquiv` in the previous session:
  `symPowEquivSymTensor {n} (hfac)` mentions `V` only in its result type, so any application
  fails with "Function expected at … but this term has type … ?m.14".
* `Fintype.sum_equiv e _ _ h` infers `f` and `g` from the goal fine for a plain sum, but got stuck
  with `AddCommMonoid ?m` once the summands were nested `smul`s (the antisymmetrizer). Pulling the
  identity out into a `have` with both functions written explicitly fixed it.
* After `rw [Equiv.coe_mulLeft, …]` the residual `(fun x ↦ τ * x) σ` is not beta-reduced, so a
  follow-up `rw [Equiv.Perm.sign_mul]` fails to match. `simp only [Equiv.Perm.sign_mul, …]` does
  the beta reduction and matches.
* `Equiv.Perm.sign` lands in `ℤˣ`, so casting to `k` needs `Units.val_mul` before `push_cast`,
  and `sgn σ * sgn σ = 1` is `Int.units_mul_self` composed with `Units.val_one`
  (`sign_cast_mul_self`).
