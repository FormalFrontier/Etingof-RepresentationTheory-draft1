## Decisions and patterns worth reusing

- **Exhaustiveness via a single idempotent.** To show every simple module `M` over the upper
  triangular algebra `S` is some `Vᵢ`, avoid building `S/Rad(S) ≅ kⁿ` and transporting
  modules. Instead work entirely inside `S`:
  1. `Rad(S)` annihilates `M` (`IsSemisimpleModule.jacobson_le_annihilator` plus the already
     proved `radical_upper_triangular`; a simple module is semisimple by instance).
  2. `∑ᵢ Eᵢᵢ = 1`, so some `Eᵢᵢ • m₀ ≠ 0`.
  3. `Eᵢᵢ * s - s * Eᵢᵢ` is strictly upper triangular, so `m ↦ Eᵢᵢ • m` is `S`-linear. It is
     idempotent and nonzero, so by simplicity its kernel is `⊥`, so it is the identity.
  4. `(s - algebraMap k S sᵢᵢ) * Eᵢᵢ` is strictly upper triangular, so every `s` acts as the
     scalar `sᵢᵢ`. Then `c ↦ algebraMap k S c • m₀` is an `S`-map `Vᵢ → M`, nonzero, hence an
     isomorphism.

  The point is that all the "modulo the radical" reasoning stays as explicit ideal
  memberships in `S`; no quotient ring, no `IsTwoSided` instances, no scalar-restriction
  diamond.

- **One-dimensional representations of a `k`-algebra `A`.** Defining them as
  `def V (i) : Type _ := k` with `Module A V := Module.compHom V (χ i).toRingHom` is much
  smoother than `A ⧸ RingHom.ker (χ i)`: `finrank = 1` is `Module.finrank_self`, and the
  action lemma is `rfl`. Because the carrier is a plain `def` (not `abbrev`), instance search
  does not unfold it, so there is no clash with `Module k k`. Inside proofs, move between the
  two views with `show k from v` / `change`.

- **A simple module carries no `k`-action a priori.** State classification results purely
  `A`-linearly (`M ≃ₗ[A] Vᵢ`) and, in the proof, get scalars from `algebraMap k A` rather
  than assuming `[Module k M] [IsScalarTower k A M]`.

- **`Matrix.single` argument counts.** `Matrix.single_apply_of_ne`,
  `Matrix.single_mul_apply_of_ne`, and `Matrix.mul_single_apply_of_ne` take several explicit
  index arguments before the hypothesis, so positional `_ _ _ _ h` silently misaligns and the
  error surfaces as a bogus `Type` mismatch. Wrapping the entry computations in local lemmas
  (`single_diag_mul_apply`, `mul_single_diag_apply`, stated with an `if`) and then using
  `split_ifs` is far more robust than `rw`-ing the Mathlib lemmas directly.
