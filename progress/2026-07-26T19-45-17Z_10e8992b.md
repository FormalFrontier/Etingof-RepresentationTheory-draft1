## Key patterns discovered

- **Explicit-discriminant style extends to morphisms.** `Definition6_6_3.lean`
  parametrises `objAt`/`acmAt`/`modAt`/`mapAt` by an explicit
  `d : Decidable (v = i)`. Doing the same for `homAt` makes every functor law and
  naturality proof a two-line `cases da <;> cases db` — no `HEq` transport at all,
  in contrast to the ~100-line `HEq` proofs the object-level API needed. State the
  laws **pointwise** (`homAt f i v d x = ...`), not as equalities of `LinearMap`s:
  the pointwise form needs no ambient instances, so it elaborates without `letI`
  in the statement.

- **`DirectSum.lof` takes a `DecidableEq ι` argument**, so `rfl` fails between a
  `classical`-produced `Classical.propDecidable` instance and any other. Two
  fixes, both used here: pin the instance with
  `letI : DecidableEq _ := Classical.decEq _` in the definition *and* in every
  proof (plus side), or take the instance as an explicit argument `d` and open the
  proof with `have : d = Classical.decEq _ := Subsingleton.elim _ _; subst this`
  (minus side, needed because `sourceMap` bakes in its own `classical` instance).

- `Etingof.ArrowsInto`/`ArrowsOutOf` are plain `def`s over `Σ`, so `rw` with
  lemmas mentioning `a.fst` can fail on type-correctness at `instances`
  transparency. `simp only [DirectSum.component.of, dif_neg hba, map_zero]` works
  where the corresponding `rw` chain does not.
