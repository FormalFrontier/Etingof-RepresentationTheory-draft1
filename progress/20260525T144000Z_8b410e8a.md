### Note on the Step 2 match

Merging a self-handoff PR with `QUEUED`/`IN_PROGRESS`
checks is safe in this project because the diff is a single
progress file under `progress/` and cannot affect Lean
build, lint, or correctness. The Step 2 filter as written
(`length > 0` AND no `FAILURE`/`CANCELLED`) intentionally
permits this — empty `conclusion` strings (for `QUEUED` /
`IN_PROGRESS` checks) satisfy `!= FAILURE` and
`!= CANCELLED`. If branch protection had blocked the merge,
`gh pr merge` would have returned an error and the PR would
remain queued for a later cycle.

### Why no `return-to-human`

`return-to-human` requires zero broken PRs. The 4
`CONFLICTING` / `FAILURE` PRs in `/repair` scope keep the
project out of fully-converged state. The `/repair` agent
loop owns those, not the planner.

### Why no `set-target`

Per `/plan` Step 6: only call `set-target` when fully
converged (call `return-to-human` instead) or in the tail
phase with a small number of in-flight streams that future
planning genuinely depends on. Neither applies here. The
project is steady-state idle on the math axis with `/repair`
holding the only active work stream — shrinking the agent
pool would starve the repair workers if conflicts spike.
