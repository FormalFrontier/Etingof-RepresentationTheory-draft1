**Issue #7388, `Chapter9/Problem9_3_2.lean`.** The algebra is
`A = ℂ⟨g, x⟩ / (gx + xg, x², g² - 1)`.

Classification of the simple modules (first of the three things the problem asks for):

- `exists_mul_eq_mul_x`: `x A ⊆ A x`, so `A x` is a two-sided ideal. Proved by induction over
  the free algebra through `RingQuot.mkAlgHom_surjective`.
- `xAnnihilator`, `x_smul_eq_zero_of_isSimpleModule`: `A x` has square zero, so the
  `x`-annihilator of a simple module is a nonzero submodule, hence everything.
- `smul_mem_of_g_stable`: once `x` acts as zero, every `g`-stable `ℂ`-subspace is an
  `A`-submodule (`g` and `x` generate `A`).
- `g_smul_eq_self_or_neg`: the `+1` eigenspace of the involution `g` is then an `A`-submodule,
  so `g` acts as `+1` or as `-1`.
- `isSimpleModule_complex`, `finrank_eq_one_of_isSimpleModule`: therefore every `ℂ`-subspace is
  an `A`-submodule, so a simple module is one-dimensional.
- `equivSplusOfGSmulEqSelf`, `equivSminusOfGSmulEqNeg`, `nonempty_linearEquiv_splus_or_sminus`,
  `not_linearEquiv_splus_and_sminus`, and the packaged
  **`simple_module_classification : Xor (Nonempty (S ≃ₗ[A] Splus)) (Nonempty (S ≃ₗ[A] Sminus))`**.

Indecomposability and projective covers (part of the second thing):

- `socle_mem_of_ne_bot_Pplus` / `eq_top_of_mem_Pplus` (and the `Pminus` analogues) pin the

## Note for the next agent working in this repo

The lakefile sets `weak.backward.isDefEq.respectTransparency = false` under `[leanOptions]`.
`lake env lean <file>` does **not** apply lakefile options, so files in this project can appear
to have dozens of spurious "unsolved goals: `0 = 0`" errors when checked that way. Either use
`lake build`, or pass the options explicitly:

```
lake env lean -D backward.isDefEq.respectTransparency=false -D relaxedAutoImplicit=false \
  -D maxSynthPendingDepth=3 <file>
```
