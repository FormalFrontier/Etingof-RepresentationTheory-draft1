## Accomplished

Fixed issue #7554: `EtingofRepresentationTheory/Chapter5/RepresentationAsModuleHom.lean`
now elaborates from source (`lake env lean` exit 0) with no `sorryAx`.

Root cause: a transparency regression. The terminal reflexivity of `rw`/`simp`
now runs at reducible transparency and no longer unfolds `Representation.asModule`
(a `def := V` whose `AddCommMonoid`/`Module` instances are defeq to, but
syntactically distinct from, `V`'s). So the `zero`/`add` cases of all four
`map_smul'` proofs stopped closing: the two `MonoidAlgebra` actions (and
`map_zero`/`map_add`) agree only after unfolding `asModule`.

Fixes:
- `asModule_directSum_equiv`, `asModuleHomOfIntertwiner`, `asModuleEquivOfIntertwiner`:
  close each `zero`/`add` case with an explicit `exact rfl` / `exact map_zero f`
  at default transparency; split `f` over the `asModule` add with a pinned
  `show f (a•x + b•x) = f (a•x) + f (b•x) from map_add f _ _` term (a bare
  `rw [map_add]` cannot match `asModule`'s add instance at reducible transparency).
- `asModule_trivial_tprod_equiv_aux`: redefined to reuse
  `asModuleEquivOfIntertwiner (tprodSplitEquiv b) (tprodSplitEquiv_intertwines b σ)`.
  The old inline structure's `single_smul` rewrite failed because
  `tprodSplitEquiv`'s concrete `DirectSum β W` codomain leaked past the `asModule`
  action. Reusing the generic (now-robust) intertwiner lift avoids re-deriving
  through the leaky codomain. This required moving the `Intertwiner` section
  ahead of `TrivialTprodSplit`.

All public names, signatures, and `_apply` simp lemmas preserved. Public API
audited: depends only on `propext`, `Classical.choice`, `Quot.sound`.
