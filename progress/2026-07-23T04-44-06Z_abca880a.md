`lake env lean EtingofRepresentationTheory/Chapter6/CoxeterInfrastructure.lean` now

Root cause: the v4.31/v4.32 Mathlib/toolchain bump changed instance resolution so the
old `letI : AddCommGroup (DirectSum …)` shadowing trick broke `Module k₀ (DirectSum …)`
synthesis, and a couple of finrank/`Finset.univ` idioms drifted. Fixes:

- `reflFunctorPlus_free_eq`: the reflected space at `i` is `ker(sinkMap)`, a submodule of
  the direct sum `⊕ⱼ Vⱼ`. Capture the kernel's own `Module` instance first, build its
  ring-induced `AddCommGroup` from it, and apply `Module.Free.of_divisionRing` (every vector
  space is free), then transport along the existing equivalence. Avoids the shadowing that
  regressed synthesis.
- `reflFunctorPlus_finite_eq`: establish `Module.Finite k₀ (⊕ⱼ Vⱼ)` via the DirectSum↔Pi
  linear equivalence (`Module.Finite.pi`), then `IsNoetherian` via
  `isNoetherian_of_isNoetherianRing_of_finite` (AddCommGroup passed as an explicit term, no
  shadowing). Submodule finiteness then follows automatically and transports along the equiv.
- `simpleReflectionDimVector_eq_simpleReflection`: the `x ∈ Finset.univ` goal (line ~1355)
  now closed with `iff_of_true (Finset.mem_univ x) (@Finset.mem_univ _ sigmaFT x)`, pinning
  the second `Fintype` instance explicitly instead of relying on `simp`.
- `indecomposable_reduces_to_simpleRoot` and `Corollary6_8_2` `hd_nonzero` proofs: replaced
  the `addCommGroupOfRing` + `finrank_pos`/`finrank_zero_iff` route (which failed instance
  synthesis) with `Module.finrank_eq_zero_iff_of_free`, matching the working pattern already
  used a few lines above at line 1594.
