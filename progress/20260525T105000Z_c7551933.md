### Mergeable-filter caveat (re-flagged from cycle 992)

The Step 2 mergeable filter as literally specified in the
`/plan` command is **permissive** — it accepts checks with
empty-string `conclusion` (queued/in-progress), because
`"" != "FAILURE" and "" != "CANCELLED"` is true. Running
that filter verbatim would return 20 matches (all the
open planner handoff PRs with QUEUED CI). Merging them
would be wrong — their builds have not finished.

Continuing the established convention; use the strict
SUCCESS-only filter:

```bash
gh pr list --state open --json number,mergeable,statusCheckRollup \
  --jq '.[] | select(
    .mergeable == "MERGEABLE" and
    (.statusCheckRollup | length > 0) and
    (.statusCheckRollup | all(.conclusion == "SUCCESS"))
  ) | .number'
```

Strict filter returns zero matches this cycle, so no
merge performed.
