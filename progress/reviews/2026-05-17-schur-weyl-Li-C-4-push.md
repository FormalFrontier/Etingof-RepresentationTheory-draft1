### Q2b — `DirectSum.of_smul` is the right lemma: PASS

`Mathlib.Algebra.DirectSum.Module:93`:
```
theorem of_smul (i : ι) (c : R) (x) : of M i (c • x) = c • of M i x :=
  (lof R ι M i).map_smul c x
```

The use site (line 271–274) needs to commute `α • _` past
`DirectSum.of β iLam` after substituting `f iLam = α • π`:
```lean
rw [happly_e, hπ_special, LinearMap.smul_apply, hπv₀,
    ← TensorProduct.smul_tmul', DirectSum.of_smul]
```
Step-by-step (LHS reduces to RHS):
- `happly_e`: `e (c.val (e.symm ...))` → `DirectSum.of β iLam (f iLam v₀ ⊗ₜ l)`
- `hπ_special`: `f iLam` → `α • π`
- `LinearMap.smul_apply`: `(α • π) v₀` → `α • π v₀`
- `hπv₀`: `π v₀` → `v₀`
- `← TensorProduct.smul_tmul'`: `(α • v₀) ⊗ₜ l` → `α • (v₀ ⊗ₜ l)`
- `DirectSum.of_smul`: `DirectSum.of β iLam (α • (v₀ ⊗ₜ l))` → `α • DirectSum.of β iLam (v₀ ⊗ₜ l)`

The worker's diagnosis is correct: the original `map_smul` failed
because `DirectSum.of` is an `AddMonoidHom`, not a `LinearMap`, so no
`MulActionHomClass` instance exists. `DirectSum.of_smul` is the
specific bypass and is exactly `(lof R ι M i).map_smul` in disguise
(the lemma's RHS goes through the `lof` wrapper which *is* a
`LinearMap`).

## Findings for follow-up (filed as a separate `feature` issue)

PR #2697 introduced two patterns the project tolerates but the linter
flags:

1. **Section-level `set_option synthInstance.maxHeartbeats 800000`**
   (line 887) → `linter.style.setOption` (unscoped option). Mathlib
   style is to scope per declaration via `set_option ... in`.
2. **Comment before `set_option maxHeartbeats 1600000 in`** (lines
   1000–1002) → `linter.style.maxHeartbeats` wants the comment
   *between* the `set_option` and the declaration.
3. **Three `show`-tactic-changes-goal warnings** at lines 915, 1046, 1059
   (`linter.style.show`). PR #2698 cleaned up the same pattern in its
   file; PR #2697 did not.
4. **Heartbeat over-provision** — the section `synthInstance` bump and
   the bridge-theorem `max` bump are each ~4× tighter than necessary
   (passes at 200000 / 400000; fails at 100000 / 200000).

None of these are regressions; all post-date PR #2697 but live in a
file that already has dozens of style warnings. Recommendation: a
single janitorial PR that scopes the section option, moves the comment,
and tightens both bumps to the empirical minima + 2× safety buffer.
