## Accomplished

Fixed the Clebsch–Gordan module-source regression (#7529): restored
`EtingofRepresentationTheory/Chapter2/Problem2_15_1_m_Module.lean` to a clean
direct build.

Root cause: a Mathlib change made `c • (e_i ⊗ₜ e_{k−i})` in `cgHW` (and the
iterated-lowering vectors) elaborate with `TensorProduct.instSMul`, whereas
Mathlib's `lie_smul` (`⁅x, c • m⁆ = c • ⁅x, m⁆`) is keyed on the abstract
`Module`-derived scalar-multiplication instance. The two instances are
definitionally equal, but `rw`/`simp` match on the discrimination-tree key, so
every `rw [lie_smul]` over the concrete tensor product failed with
`Did not find an occurrence of the pattern ⁅?x, ?t • ?m⁆` (8 sites: lines 175,
209, 322/323, 437, 460, 474, 504, 514).

Fix: added a small public helper `lie_smul_cg` stated with the concrete tensor
type `(Fin (lam+1) → ℂ) ⊗[ℂ] (Fin (mu+1) → ℂ)` — so its statement's `•` is the
same `TensorProduct.instSMul` used by the goals — and proved it by `lie_smul`
(defeq). Replaced the 8 failing `lie_smul` rewrites with `lie_smul_cg`. Left the
two general-`M` ladder uses of `lie_smul` (lines 90, 105) untouched — those
already matched. Also dropped an unused `Fin.val_mk` simp argument the linter
flagged once the file elaborated.

No `sorry`/`admit`/axiom added; #7427's independent semantic requirements
untouched.
