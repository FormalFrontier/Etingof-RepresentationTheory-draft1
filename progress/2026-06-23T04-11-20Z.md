## Accomplished

Adapted the project's proof content to Lean 4 v4.29.0-rc7. All changes are
deprecation-driven, no statement changes, no new sorries.

rc7 deprecated `MonoidAlgebra.mapRangeRingHom` (and `_apply`, `_single`,
`coe_`) in favour of `MonoidAlgebra.mapRingHom`, and made `mapRingHom_apply`
/ `mapRingHom_single` `@[simp]`. Because the deprecated names are aliases
whose lemma *statements* are phrased about `mapRingHom`, `rw`/`simp` could no
longer match the `mapRangeRingHom` head symbol, producing `unsolved goals`,
`simp made no progress`, and `rewrite did not find pattern` errors. Fix:
rename `mapRangeRingHom*` → `mapRingHom*` throughout the affected files.

rc7 also made the object argument of
`projective_iff_hasProjectiveDimensionLT_one` implicit; dropped the explicit
argument at each call site (`Function expected at` errors).

Files changed:
- Chapter5/Corollary5_12_4.lean — φ now uses `mapRingHom`; simp arg renamed.
- Chapter5/Theorem5_22_1.lean — global `mapRangeRingHom` → `mapRingHom`
  (fixed all 8 errors; the `YoungSymmetrizerK_eq_mapRange` statement now
  produces `mapRingHom`, which downstream files rely on).
- Chapter5/Theorem5_4_4.lean — φ now uses `mapRingHom`.
- Chapter5/Theorem5_12_2_DistinctGeneral.lean, SpechtCharacterGeneral.lean,
  SchurWeylSpecialBlockGeneral.lean — `mapRangeRingHom` → `mapRingHom`.
- Chapter9/ShapiroLemma.lean, Chapter9/Example9_4_4.lean — dropped explicit
  arg from `projective_iff_hasProjectiveDimensionLT_one`.
- Infrastructure/SpechtModuleSimple.lean — `mapRangeRingHom` → `mapRingHom`
  (transitive dependency of CI-built Chapter5 files).
