## Decisions made / patterns discovered

- **One coefficient-indexed family beats two normal forms.** Indexing `twoRep` by
  `c : (Σ a b : Q, (a ⟶ b)) → k` — a function on *all* arrows, not just `i ⟶ j` — keeps the
  definition transport-free (`truncMap` zeroes out every arrow whose source is not `i` or target
  not `j`, so the off-support values of `c` are irrelevant), while `c = 0` recovers `S_i ⊕ S_j`
  and `i = j` recovers `S_i ⊕ S_i`. Making `c` a function on `i ⟶ j` instead would push a
  dependent transport into the *definition*, where every downstream `rw` would fight it.
- **`h ▸ t` silently rewrites the wrong occurrences; use a named transport instead.** Building a
  vertexwise family `∀ v, ρ.obj v ≃ₗ[k] (twoRep i j c).obj v` by
  `if hv : v = i then hv ▸ Ti else if hv' : v = j then hv' ▸ Tj else …` fails on the *second*
  branch: `hv' : v = j` rewrites `j → v` in the expected type too, so Lean demands
  `ρ.obj v ≃ₗ (twoRep i v c).obj v`. Fix: a tiny helper
  `transportEquivAt (h : v = w) (φ : ρ.obj w ≃ₗ σ.obj w) : ρ.obj v ≃ₗ σ.obj v := by subst h; exact φ`
  with `@[simp] transportEquivAt_rfl … = φ := rfl`. Then `rw [normalFormEquivAt, dif_pos rfl,
  transportEquivAt_rfl]` gives clean unfolding lemmas at the two distinguished vertices.
- **`subst h` picks which variable to eliminate, and it is usually not the one you want.** With
  `ha : a = i` (`a` from `intro`, `i` a theorem binder) `subst ha` eliminated `i`, breaking every
  later mention of `i` in the proof. `subst a` names the victim explicitly and keeps `i`. Same
  for `rcases … with rfl`, which offers no such control — prefer `obtain h`, then `subst <var>`.
- **`commutes` only has content at one arrow.** For a representation supported on `{i, j}` the
  isomorphism's `commutes` field is trivial (`0 = 0`) for every arrow other than `i ⟶ j`: either
  `ρ`'s map vanishes and the normal form's `truncMap` has a zero-dimensional source/target. So
  the explicit trivializations are needed at exactly two vertices, and the general-`v` branch can
  be `subsingletonEquiv`.
- **`simp only [coeffOf]` already discharges the `dite`s.** Unfolding a `dite`-with-transport
  definition at a point where both conditions are `rfl` reduces the conditions to `True` and the
  `▸`s away, so `simp [coeffOf]` closes `coeffOf α β ⟨i, j, e⟩ = β (ρ.mapLinear e (α.symm 1))`;
  the `rw [dif_pos rfl, dif_pos rfl]` I reached for first fails because the conditions are gone.
- **`rw [hx]` where `hx : x = f x`-shaped rewrites the RHS too.** Substituting
  `x = α x • α.symm 1` looped into the goal's own `α x`. State the equation one level up
  (`ρ.mapLinear e x = α x • ρ.mapLinear e (α.symm 1)`) so the pattern occurs only where wanted.
