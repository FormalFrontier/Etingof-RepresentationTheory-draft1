- **Part (ii) negative direction** — `Hom(ℤ/2ℤ, -)` is not right exact. Added
  `Etingof.subsingleton_hom_zmod_int` (`Hom(ℤ/2ℤ, ℤ) = 0`, since `ℤ` is
  torsion-free) and `Etingof.hom_not_right_exact`: for any surjection

  identity, so it is not surjective.

  `TensorProduct.rid`) and `Etingof.tensor_not_left_exact`: applying
  `lTensor (ℤ/2ℤ)` to the injection `(· * 2) : ℤ ↪ ℤ` kills `1 ⊗ 1`, hence is not
  injective.

## Next step

Gap (c) is a genuine Mathlib limitation, not an oversight: Mathlib's `TensorProduct`
base ring must be a `CommSemiring`, and its `ModuleCat` monoidal-closed structure is
built over a commutative ring, so there is no in-library noncommutative bimodule
tensor product to phrase `X ⊗_A -` for noncommutative `A`. The docstring documents
this accurately. If a future agent wants full fidelity, it would require either
upstreaming noncommutative right-exactness of `lTensor`/`rTensor` or accepting the
commutative specialization. Recommend closing #5647 as substantially addressed.

## Blockers

None. Gap (c) is documented as an accepted Mathlib-API limitation, not a blocker.
