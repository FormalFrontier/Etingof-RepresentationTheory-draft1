## Why decompose (not attempt inline)

The crux is *not* a single short lemma. Two facts make it monolithic and
orientation-dependent, so it does not fit one reliable session:

1. **No center self-map.** Each K_{1,4} arm is one arrow oriented one way
   (leaf↔center), so the representation gives no center→center endomorphism; the
   eigenvalue workhorse (needs a nilpotent with `ker` dim 1) cannot run on the
   `2(m+1)`-dim center directly. It must run on a leaf `F^{m+1}` (the model uses
   leaf 1), forcing a leaf→center reconstruction afterwards.
2. **Per-orientation leaf shape.** The center subspace `U = W₁⟨0⟩` decomposes
   differently per orientation: with all arms forward, `core`
   (`FieldGenericTube.lean:135`) gives the clean block `U = W₁⟨1⟩ × W₁⟨2⟩`; a
   *reversed* coordinate arm replaces the relevant half by a skew projection
   (`reversed_leaf_subspace_eq` pins `W₁⟨i⟩ = (W₁⟨0⟩).map starProj_i_F`), so the
   block decode and the leaf→center reconstruction are both genuine
   case-trees, not one uniform argument. Reconstruction is uniform *in effect*
   only because the four arm ranges/kernels always span/intersect correctly
   (all-forward: `range e1 + range e2 = ⊤`; all-reversed:
   `ker starProj3 ∩ ker starProj4 = H₁ ∩ H₂ = ⊥`), but proving it needs the
   per-arm split.

This is the shared family-wide wall: no sibling (Ẽ₆ `etilde6Rep_kQ_isIndecomposable`,
Ẽ₇) has cracked it — both are still bare `sorry`. Cracking D̃₄ via #4702/#4703
sets the template for them.
