## Key findings / route

- The existing tensor-power embedding infrastructure
  (`polynomialRep_embeds_in_tensorPower`, `polynomial_homog_rep_equivariant_embedding`)
  is **circular** for this goal: it takes `h_span` as a hypothesis (the
  det⁻¹-elimination / coefficient-homogeneity it needs is derived from `h_span`
  via `scalarGL_acts_as_pow`). So the embedding route cannot *prove* `h_span`.

- Used instead a **self-contained orthogonal-idempotent / torus-coefficient**
  argument. Restricting the polynomial matrix coefficients to the diagonal torus
  `diag(t)` gives operators `T(t) = ∑_μ tᵘ • Cmat μ`; the homomorphism property
  `T(t·s)=T(t)T(s)` plus `T(1)=1`, combined with Zariski density of `(kˣ)^N` over
  the infinite field, force `{Cmat μ}` to be a complete system of orthogonal
  idempotents (`Cmat μ * Cmat ν = δ_{μν} Cmat μ`, `∑ Cmat μ = 1`). The operators
  `Cop μ` are then weight projectors with `range (Cop μ) ≤ glWeightSpace μ` and
  `∑ Cop μ = id`, giving saturation.

- The density primitive is `MvPolynomial.eq_zero_of_eval_eq_zero_off_zeroLocus`
  (in `EvalEqOnGL`), specialized via `Q = ∏ Xᵢ` to "vanishing on the torus
  ⇒ zero polynomial". Reusable matrix-valued forms `matrix_torus_density` /
  `matrix_torus_density_units` are exported.

- Defined `Etingof.IsPolynomialRepresentation` (D-free: coefficients in
  `k[Xᵢⱼ]`, no `D=det⁻¹`) and a bridge
  `IsPolynomialRepresentation.isAlgebraic` connecting it to the existing
  `IsAlgebraicRepresentation` API (via `rename Sum.inl`).

- Reused the existing `Etingof.diagTorus k N` from `FormalCharacterTorusTrace`
  rather than redefining (avoided a name collision).
