Changes:

- **`agent-worker-flow` Step 2 restructured into ordered 2a/2b/2c.** Previously
  the `reset --hard origin/main` instruction came *first* and the "check
  `git status` before that reset" guard came ~10 lines later — and the guard
  block plus the pure-deletions and re-read-the-skill blocks were each present
  **twice** verbatim (the section had grown by append). An agent reading top-down
  hit the destructive command before the guard. Now:
  - **2a** snapshots unconditionally, *before* any branch operation:
    `git status --porcelain`, then `git diff HEAD > /tmp/$POD_SESSION_ID-stale.patch`
    and `git stash push -m "pod $POD_SESSION_ID pre-reset"` if non-empty. The
    snapshot happens before the agent judges whether the changes matter, which is
    the whole point — the judgement is what was going wrong.
  - **2b** is the skill-staleness check (`wc -l` vs `git show HEAD:`).
  - **2c** creates/resets the branch; the `reset --hard` is now explicitly
    annotated as safe *only because* 2a ran, with a back-pointer if it did not.
  - Duplicated blocks collapsed: 604 → 594 lines despite added content.
- **`git stash push` (never `-u`)** is now the prescribed remedy, so untracked
  files are left in place per the operator's standing rule, and the set-aside
  work lives on a named recoverable ref instead of being destroyed. Verified in a
  scratch repo: untracked files survive, and `git stash show --numstat` reports
  `0  2  f.md` for a deletions-only change — the exact accidental-revert signal.
- **The other unguarded `reset --hard`** (line 79, basing a branch on an unmerged
  PR head) now requires the 2a snapshot and a clean tree.
- **`pr-repair-flow` Step 2 has the mirror-image hazard fixed.** It said
  `gh pr checkout <pr-number>` with no worktree check; in a dirty reused worktree
  that drags a prior session's edits onto the PR head branch, where Step 6's
  `git push --force-with-lease` publishes them into *someone else's* PR. Same
  snapshot procedure added there.
- `origin/master` → gone from `.claude/` entirely (it was already fixed on `main`;
  it was only present in the stale working-tree copy this session restored).
