## Notes for the next agent

Two Lean-level frictions cost real time and are worth knowing:

* Mathlib's `mapBifunctor` API is phrased through `GradedObject` layers that are only
  *definitionally* equal to the `HomologicalComplex` spellings, so `rw`/`simp only` frequently
  fail to match with a "target expression is not type-correct under `instances` transparency"
  note. `set_option backward.isDefEq.respectTransparency false` (used file-wide here, as Mathlib
  does in `ShortComplex/HomologicalComplex.lean`) fixes most of it; where it does not, state the
  needed equation as a `have` in exactly the spelling that appears in the goal and `rw` that, or
  close with `exact` (which unifies at default transparency).
* `Etingof.tensorComplex C D` is a plain `def` for `HomologicalComplex.tensorObj C D`. Mathlib's
  `cyclesMap` / `homologyπ` / `iCycles` API produces the `tensorObj` spelling, and mixing the two
  makes `rw` unable to assign the complex metavariable. This file therefore uses `tensorObj`
  throughout and records `Etingof.tensorComplex_eq` (`rfl`) as the bridge.
