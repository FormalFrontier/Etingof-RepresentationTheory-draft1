## Key decision: downstream-file pattern (deviation from the issue's "Route 1")

The issue suggested adding `import …Theorem5_12_2_ClassificationGeneral` and the sub-B1 file
**to `Theorem5_22_1.lean`**. That is an **import cycle**: both files transitively import
`Theorem5_22_1` via `Infrastructure.SpechtModuleSimple`. Per the documented ℂ→general-`k`
downstream-file pattern (`lean-formalization` SKILL.md lines 585-606, established in #5004), the
general-`k` bridge lives in a **new downstream file** instead; the ℂ original is untouched. The
private ℂ declarations cannot be reused (they are `private`), so they are re-stated over `k`.

The consumer `SchurWeylSpecialBlockGeneral.lean` (#4975 sub-C) defines `spechtBlockCharacterK`
to be *definitionally equal* to `spechtModuleCharacterK`, so it reconciles the new bridge's
output by `rfl`.
