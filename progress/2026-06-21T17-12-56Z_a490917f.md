## Gotcha for successors (cold-cache defeq blowup)

`polyRightRep k N g f = rTransAlgHom (↑g) f` is `rfl`, but proving it inline as a
fresh `have ... := rfl` (or relying on the defeq via `exact`) **diverges at whnf**
(times out even at 1.6M heartbeats) when done in a downstream file — the two
FunLike coercion paths (`Representation`/`LinearMap` vs `AlgHom`) force Lean to
whnf into `aeval`. Yet the identical `rfl` is cheap *inside*
`PolynomialGLRightAction.lean` (where `polyRightRep_apply_X` already uses it). Fix:
the equation now lives as the lemma `polyRightRep_apply` in that file, so
downstream code uses `rw [polyRightRep_apply]` (no rfl re-elaboration) and then
lets Lean infer the matrix argument with `_` (avoids reconciling two `↑g`
spellings, which re-triggers the blowup). Reuse this lemma rather than re-deriving
the defeq.
