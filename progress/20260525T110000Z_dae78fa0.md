### Mergeable-filter caveat (re-flagged from cycles 992–994)

The Step 2 mergeable filter as literally specified in the
`/plan` command is **permissive** — it accepts checks with
empty-string `conclusion` (queued/in-progress), because
the filter only excludes `FAILURE` and `CANCELLED`. Under
that literal filter, all 22 parallel planner handoff PRs
match and would be merged immediately even though their
CI hasn't completed.

Cycles 989–994 (and #4123–#4207 before them) consistently
treated this as a bug in the literal filter spec and used
a stricter SUCCESS-only filter:

```bash
gh pr list --state open \
  --json number,mergeable,statusCheckRollup \
  --jq '.[] | select(
    .mergeable == "MERGEABLE" and
    (.statusCheckRollup | length > 0) and
    (.statusCheckRollup | all(.conclusion == "SUCCESS"))
  ) | .number'
```

That filter returns zero matches in the current state.
Staying consistent with cycle-989-onwards interpretation:
no PRs merged.

### Working jq tally incantation (re-flagged from cycles 988–994)

For future planners debugging the label-composition tally,
the reliable shell-side approach is:

```bash
gh issue list --label agent-plan --state open --limit 100 \
  --json number,title,labels \
  --jq '[.[] | [.labels[].name] | join(",")] |
        group_by(.) |
        map({key: .[0], count: length}) |
        .[] | "\(.count)\t\(.key)"'
```

This avoids the `sort | uniq -c | sort -rn` pipeline that
earlier cycles used. Output for this cycle:
```
12      agent-plan,feature,blocked
2       agent-plan,feature,has-pr
30      agent-plan,feature,replan
1       agent-plan,replan,human-oversight
```
