## Decisions

* **Two module structures on one carrier.** `V(α,c)` and `V(α',c')` are both carried by
  `Fin p → k`, so a `letI`-based statement would silently use the *same* `Module` instance on
  both sides — a vacuous statement, since `LinearEquiv.refl` would always inhabit it. `FamEquiv`
  is therefore an `abbrev` for an `@LinearEquiv` with both instances given positionally. The
  statement is self-certifying against the collapse: if both slots held the same instance the
  reverse direction (`LinearEquiv.refl`) would contradict the forward direction, so the proved
  iff could not exist.
* **`FamEquiv` is an `abbrev`, so dot notation does not work on it.** `e.intertwines` fails with
  "does not have a usable parameter of type `FamEquiv ...`" because `e`'s type elaborates to
  `LinearEquiv ...`. The helper lemmas are named `famEquiv_intertwines` /
  `famEquiv_map_smul_field` and applied prefix-style.
* **`omit [CharP k p]` is not available for anything mentioning `FamEquiv`.** `famRep` depends on
  `CharP` (through `famRel` → `wY_eq`), so every statement about the family carries it. The
  earlier operator-level lemmas in the file can and do omit it.
* **Recovering `α` from the equivalence.** `Module.compHom` makes `a • f` defeq to
  `famRep α c a f`, so `famEquiv_intertwines` is literally `map_smulₛₗ`. `AlgHom.commutes` plus
  `Module.algebraMap_end_apply` then turns the `algebraMap` case into `k`-linearity. Comparing a
  single nonzero coordinate (`mul_right_cancel₀`) is more robust than `smul_eq_zero`, which would
  need a `NoZeroSMulDivisors` instance.
* `push_neg` is deprecated in this toolchain (v4.32.0-rc1); `Function.ne_iff` gives the nonzero
  coordinate directly.
