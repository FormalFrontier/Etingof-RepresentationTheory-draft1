- `barMerge n (i : Fin n) : ⨂[k]^(n+1) A →ₗ[k] ⨂[k]^n A`,
  `tprod v ↦ tprod (Fin.contractNth i.castSucc (·*·) v)`.

Supporting these, three reusable combinatorial lemmas were proved:
`contractNth_update_castSucc`, `contractNth_update_succ`, `contractNth_update_of_ne` —
they characterize how updating one input coordinate of `Fin.contractNth (castSucc i) (·*·)`
changes exactly one output column (`Fin.predAbove i j`), which gives multilinearity of the
merge map without any hand `map_update_add`/`smul` grind on the raw tprod.

## Current frontier

`barMerge` is intentionally indexed by `i : Fin n` (the `n` mergeable adjacent pairs), not
`Fin (n+1)`: the `Fin.last n` index would be `Fin.init` (drop last factor), which is *not*
multilinear and is handled instead by `barSnocSplit`. The #6335 blueprint already assumes the
`Fin.castSucc`-embedded interior merges, so this matches downstream.
