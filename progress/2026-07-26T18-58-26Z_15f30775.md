## Decisions and patterns

- **`Der` is a `LieSubalgebra`, not a bespoke structure.** `LieRing.ofAssociativeRing` is only a
  `local instance 100` in Mathlib, so `LieRing (Module.End k A)` is not globally synthesizable.
  The instance is nonetheless baked into `Der`'s *type* as a fixed implicit argument, so
  downstream files can write `↥(Der k A)`, `LieAlgebra k (Der k A)` and `Der.leibniz` without
  re-enabling the attribute — verified directly against a scratch file that does not import it.
  This is exactly Mathlib's own pattern for `LieAlgebra.Orthogonal.so`.
- The commutator closure proof needs `noncomm_ring` (hence `import Mathlib.Tactic.NoncommRing`);
  `ring` does not apply, and `abel` cannot distribute the products.
- Endomorphism apply-lemmas are `LinearMap.add_apply` / `LinearMap.smul_apply` /
  `LinearMap.sub_apply`, but composition is `Module.End.mul_apply` — the `Module.End.*_apply`
  spellings of the first three do not exist.
- Mathlib's `Derivation.leibniz` is stated in the `a • D b + b • D a` form against the
  `Derivation` `FunLike` coercion; bridging to the book's `D a * b + a * D b` against the
  `A →ₗ[k] A` coercion needs `Derivation.coeFn_coe` first, then `smul_eq_mul` + `mul_comm`.
