## Key pattern discovered

The `op a • m = a • m` action mismatch that blocked this issue has **two** distinct resolutions
depending on which `Module k[x]ᵐᵒᵖ (k[x]/f)` instance TC selects at the use site:
- When the *global* `Submodule.Quotient.module'` instance is picked (as in a fresh `have op a • m`
  statement), it carries `IsCentralScalar`, so `op_smul_eq_smul` closes it.
- When the `mopPolyQuot` instance baked into `ModuleCat.of k[x]ᵐᵒᵖ (k[x]/f)` is required (as by
  `tensorOverEquivTensor`'s `[Module Aᵐᵒᵖ M]` argument), `op_smul_eq_smul` produces the *wrong*
  instance and mismatches. Fix: feed the compatibility proof through a `?_` hole so Lean pins the
  expected instance, then close with `change (op a).unop • m = a • m; rw [unop_op]` (the
  `compHom` action reduces definitionally to the unop action).
For the free module `M = k[x]` (`Tor₁`), `op_smul_eq_smul` works directly.
