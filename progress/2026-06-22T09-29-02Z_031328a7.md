## DynkinTypes (22 errors) — DIAGNOSED, intentionally left for a dedicated session

Root cause (cost me a long investigation; documented so nobody repeats it):
the `split_ifs`/`omega` failures are downstream of a **matrix-entry reduction
that no longer fires**. `Matrix.sub_apply`/`smul_apply`/`one_apply` (all `@[simp]
rfl`) **silently no-op** on `(2 • 1 - DynkinType.adj t) i j` because the two
operands of the `-` have syntactically *different* index types: `1` is written
`Matrix (Fin (k+5))` but `adj` is `Matrix (Fin (DynkinType.rank (.D (k+5) _)))`.
The unreduced `rank` redex keeps the term out of simp's discrimination tree, so
`rw`/`simp`/`dsimp` all fail to match (confirmed via `pp.all` + minimal repros).

What does NOT work: `try split_ifs`, `sub_eq_add_neg`, type-ascribing the
operand (no-op cast), adding `DynkinType.rank` to the same `simp only`.

What DOES work (verified in minimal repro): rewrite `adj` to a **clean-`Fin n`-typed
lambda** first, e.g. a `rfl` unfolder
`adj_D (n h) : DynkinType.adj (.D n h) = (fun i j : Fin n => …) := rfl`, then
`rw [adj_D]` so both operands share `Fin n`; afterwards
`simp only [Matrix.sub_apply, Matrix.smul_apply, Matrix.one_apply]` fires and the
original `split_ifs <;> simp_all <;> omega` closes. Apply this to the ~13
`cartan_*` / inline `have` entry sites. The file *also* has separate
`dsimp`/`linarith`/`whnf-timeout` errors (lines ~720, 792, 850, 957, 1067) that
need individual attention.
