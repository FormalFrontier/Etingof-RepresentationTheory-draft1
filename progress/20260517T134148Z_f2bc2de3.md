## Decisions made

- **New file vs additions to `FieldGenericInfiniteType.lean`**: chose a
  new file because (a) Sub B's indecomposability proof will be large
  (~300-500 lines if it gets a real proof, or ~10 lines plus a `sorry`
  if it inherits the wall) and (b) `FieldGenericInfiniteType.lean` is
  already 1147 lines.
- **Section choice for `etilde6Gamma_F`**: picked `(u, v) ↦ (v, u-v, 0)`
  (the third block zero). Verified algebraically that
  `etilde6Gamma_F ∘ etilde6GammaInv_F = id` (the right-section identity
  — see file docstring). The choice is provisional; Sub B may need to
  revise it.
- **No inverse-relation lemmas**: tried to add
  `embed2to3_AB_reverse_F_comp`, `embed2to3_CA_reverse_F_comp`,
  `etilde6Gamma_F_comp_inv`, and the two `etilde6LeafProj_F_*` left-
  inverse lemmas, but the `simp`-based proofs ran into a `LinearMap.single`
  unfolding issue (`x : Fin n → F` got internally represented as
  `LinearMap.single F (fun i ↦ F) x 1`, which then failed `Fin.ext`
  application). The issue body marks these as "any inverse-relation
  lemmas defined here" (i.e. optional), so deferred them to Sub B —
  which will need them in concrete contexts anyway, where the proofs
  can be tailored.
- **Local `etilde6LeafProj_F` vs reusing PR #2802's `starFirst_F`**:
  PR #2802 (open, not merged) introduces `starFirst_F` with identical
  semantics. Defining `etilde6LeafProj_F` locally avoids dependency on
  an unmerged PR; once #2802 merges, a small follow-up can dedupe.
