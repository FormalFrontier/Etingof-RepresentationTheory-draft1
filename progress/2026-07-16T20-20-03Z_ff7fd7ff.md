## Key decisions / patterns

- **Cycle encoding.** Chose the edge-count form `hcyc : 2·n ≤ ∑ᵢ∑ⱼ adjᵢⱼ`
  (= "at least `n` edges") rather than `¬ SimpleGraph.IsAcyclic`. Rationale: the
  main-theorem case-split is cleanest on the edge count. A connected graph always
  has `#edges ≥ n − 1` (already used in `isDynkinDiagram_isTree`), so the `n` nat
  splits as `#edges = n − 1` (tree/acyclic, the #6793 tree case's job, giving
  `∑ᵢ∑ⱼ adjᵢⱼ = 2(n−1)`) vs `#edges ≥ n` (this lemma). No `SimpleGraph`
  round-trip needed. The tree case (#6793) should take the complementary
  `∑ᵢ∑ⱼ adjᵢⱼ = 2(n−1)` (or `≤ 2(n−1)`), so the two dovetail via `omega` on the
  edge count in the main split.
- **Simpler than the issue's route.** The issue proposed extracting a chordless
  spanning cycle + minimality contradictions. Instead: test PSD against the
  all-ones vector, `0 ≤ 1ᵀ(2Id−adj)1 = 2n − ∑ᵢ∑ⱼadjᵢⱼ`; with `hcyc` the form
  vanishes on `1`, so `affine_cartan_mulVec_eq_zero_of_form_zero`
  (Problem6_1_3_continued_tildeE.lean:969) gives `(2Id−adj)·ᵥ1 = 0`. Row `i`:
  `2 − ∑ⱼadjᵢⱼ = 0` ⟹ degree 2. `n ≥ 3` falls out (vertex 0 has two distinct
  neighbours ≠ itself). Then `two_regular_connected_iso_Atilde` (#6847, line 1364)
  finishes. Reused the `hone`/`hrow`/`hval` all-ones-row machinery verbatim from
  `isDynkinDiagram_isTree`.
