## Accomplished

Worked issue #6122 (Problem 2.16.2, the 2-dimensional Lie algebra `[X,Y]=Y`). Landed the
**characteristic-0 cluster** of `EtingofRepresentationTheory/Chapter2/Problem2_16_2.lean`,
sorry-free and axiom-clean (`propext, Classical.choice, Quot.sound`):

- `bracket_X_Y : ⁅X k, Y k⁆ = Y k` — matrix-unit computation via
  `LieRing.of_associative_ring_bracket` + `Matrix.single_mul_single_same/_of_ne`.
- `instIsSolvable : LieAlgebra.IsSolvable (g k)` — new instance. Proved by characterizing the
  underlying submodule (`g k ≤ span{e₁₁,e₁₂}`, via packaging `span{e₁₁,e₁₂}` as the Lie
  subalgebra `spanB` and `lieSpan_le`), showing every bracket lands in `span{Y}`
  (`bracket_expand`, `bracket_mem_span_Y`), so `⁅derivedSeries 1, derivedSeries 1⁆ = ⊥`.
- `charZero_irreducible_finrank_one` — reuses the Problem 2.16.1 argument, generalized from `ℂ`
  to any alg-closed char-0 `k` (Mathlib's `exists_nontrivial_weightSpace_of_isSolvable` +
  `instIsTriangularizableOfIsAlgClosed`, needing only the `instIsSolvable` above).
- `charZero_Y_acts_zero` — on a 1-dim module every `𝔤`-element acts by a homothety
  (`LinearMap.existsUnique_eq_smul_id_of_finrank_eq_one`); since `Y = ⁅X,Y⁆` its action is the
  commutator of homotheties `[cX•id, cY•id] = 0`.

Key patterns discovered:
- Bare `Matrix.single 0 0 1` defaults its index type to `ℕ`; introduced reducible `abbrev`s
  `e11`/`e12` (with `Matrix (Fin 2) (Fin 2) k` ascription) to pin the indices. `rw` won't see
  through the abbrev to match `Matrix.single_mul_single_*`, so the base bracket lemmas use
  `simp [e11, e12, ...]` (the single-mul lemmas are `@[simp]`).
- `LieAlgebra.ofAssociativeAlgebra` is a global instance that fires off the local
  `LieRing.ofAssociativeRing`, so the `k`-bilinear bracket lemmas (`smul_lie`, `lie_smul`) are
  available on matrices without extra setup; `bracket_expand` closes with `module`.
- `derivedSeries k L 2 = ⁅derivedSeries 1, derivedSeries 1⁆` holds by `rfl` (small `Nat.iterate`
  unfolds); rewriting the literal `2 → 1+1` fails with a "motive not type correct" error because
  it also hits the `2` inside `Fin 2`.
