## Decisions made / patterns discovered

* **Indexing unordered pairs.** `Theorem5_25_2_part3b` is stated with `Set` equality
  `{χ₁, χ₂} = {χ₁', χ₂'}`, so `Sym2 Chars` minus the diagonal is the matching index type.
  But `principalSeries χ₁ χ₂` and `principalSeries χ₂ χ₁` are only *isomorphic*, not equal,
  as objects of `FDRep`, so `Sym2.lift` cannot define the family. The file instead picks an
  ordered representative with `Quot.out` (`Sym2 α` is literally `Quot (Sym2.Rel α)`), which
  is sound because the two choices give isomorphic representations. `CharPair.ext_of_pair_eq`
  converts `part3b`'s set equality back to equality in `Sym2` via `Set.pair_eq_pair_iff`
  and `Sym2.eq_swap`.
* **Counting characters.** `CommGroup.card_monoidHom_of_hasEnoughRootsOfUnity` gives
  `Nat.card (G →* ℂˣ) = Nat.card G` directly. It needs
  `HasEnoughRootsOfUnity ℂ (Monoid.exponent G)`, which follows from
  `IsSepClosed.hasEnoughRootsOfUnity` once `NeZero ((Monoid.exponent G : ℕ) : ℂ)` is
  registered (from `Monoid.exponent_ne_zero_of_finite`). Both are one-line instances in the
  file. `Finite (Chars p n)` comes from the companion `MulEquiv`.
* **Instance-diamond avoidance.** `Theorem5_25_2.lean` declares
  `instance : Fintype (GaloisField p n) := Fintype.ofFinite _`, which need not be the
  instance a Mathlib `Fintype.card` lemma was stated with. Everything here is phrased in
  `Nat.card` and converted with `Nat.card_eq_fintype_card` at the last moment; note that
  `GaloisField.card` is itself already a `Nat.card` statement in current Mathlib.
* Cross-kind goals of the form `¬ (1 = p ^ n)` must be discharged with
  `simp only [Sum.elim_inl, Sum.elim_inr]` rather than bare `simp` — plain `simp` rewrites
  through `pow_eq_one_iff` into a disjunction mentioning `p = 1`, which `omega` cannot
  close. The final version sidesteps this entirely by routing through the three named
  cross-kind theorems.
