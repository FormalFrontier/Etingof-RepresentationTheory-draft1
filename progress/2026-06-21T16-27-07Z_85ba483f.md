### Root cause (different from prior ports)

Unlike #4892/#4898 (simp-normal-form drift away from defeq), these were
**instance-availability** failures. In Mathlib v4.31, `LieRing.ofAssociativeRing`
— the Lie ring structure on an associative ring via the commutator — was demoted
from a global `instance (priority := 100)` to an `@[implicit_reducible] def` with
only `attribute [local instance 100]` (see
`Mathlib/Algebra/Lie/OfAssociative.lean:50,66`). The demotion avoids a bracket
diamond when a ring acts on itself (`M = A`). Consequently:

- `Sl2Defs`: `LieAlgebra.SpecialLinear.sl (Fin 2) ℂ : LieSubalgebra ℂ (Matrix …)`
  no longer elaborates downstream, because `LieSubalgebra ℂ (Matrix (Fin 2) (Fin 2) ℂ)`
  needs `LieRing (Matrix (Fin 2) (Fin 2) ℂ)`, which is no longer a global instance.
  (Mathlib's own `Classical.lean` re-enables it locally to define `sl` —
  `Classical.lean:89` — but local instances don't propagate to importers.)
- `Example2_9_2`: the two `inferInstance` examples for `LieRing A` and
  `LieAlgebra k (Module.End k V)` fail to synthesize for the same reason.

### Fix

Add `attribute [local instance 100] LieRing.ofAssociativeRing` at file scope in
each of the two files (the name exists in both toolchains; the symbol is reachable
through the existing imports). On v4.31 this restores the needed instance; on
v4.28.1, where it is already global, the attribute is harmless (verified: build
clean, no warnings). The example bodies stay as `inferInstance` / the original
`sl` abbrev — no proof rewrites needed.

`Example2_9_2_continued.lean` takes `[LieRing L] [LieAlgebra k L]` as explicit
hypotheses, so it is unaffected — confirmed it builds clean on v4.31 untouched
(deliverable 2: no change required).
