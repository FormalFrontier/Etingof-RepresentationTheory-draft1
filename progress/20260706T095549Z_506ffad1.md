### Key modelling decision

`A₁ ⊗ A₂` is `Algebra.TensorProduct` (a `k`-algebra). The *external* tensor product module
structures on `M₁ ⊗ₖ M₂` / `N₁ ⊗ₖ N₂` over `A₁ ⊗ₖ A₂` are not defeq-safe Mathlib instances in the
noncommutative setting (`TensorProduct.Algebra.module` only handles commuting actions on a *single*
module; the right-factor action is not a default instance, and the `Tor` side needs
`Algebra.TensorProduct.opAlgEquiv : (A₁ ⊗ A₂)ᵐᵒᵖ ≃ₐ A₁ᵐᵒᵖ ⊗ A₂ᵐᵒᵖ`). Rather than construct them
(pure instance plumbing, statement-irrelevant), the theorems take the module structures as
instance parameters **pinned** by their action on simple tensors (`hN`/`hM`:
`(a₁ ⊗ a₂) • (x₁ ⊗ x₂) = (a₁ • x₁) ⊗ (a₂ • x₂)`). Simple tensors generate and the action is
additive, so the pins determine the structures uniquely — i.e. they are exactly the canonical
external tensor products. Faithful spec, no vacuous `True`.

The RHS `⨁_{j+m=i}` is a `DirectSum` over `{p : ℕ × ℕ // p.1 + p.2 = i}`; summands are `⊗[ℤ]` of
the (abelian-group-valued) `Tor`/`Ext` groups — the group-level shadow of the book's `⊗ₖ`, matching
the sibling Problem 8.2.7 convention (the `Tor`/`Ext` API forgets the `k`-linear structure).
