## Accomplished

Discharged issue #6240 (Ch3 Problem 3.9.2b): proved
`Etingof.Problem3_9_2.infinitely_many_indecomposables` in
`EtingofRepresentationTheory/Chapter3/Problem3_9_2.lean`, removing its `sorry`. For `n > 1` the
zero-multiplication algebra `B = ℂ⟨x₁,…,xₙ⟩/(xᵢxⱼ = 0)` is shown to have infinitely many
nonisomorphic indecomposable representations.

`#print axioms infinitely_many_indecomposables` reports only `propext, Classical.choice,
Quot.sound` — no `sorryAx`.

Construction (following the issue's proof strategy): the family `Mₖ = ℂ²` where `x₀` acts by the
square-zero nilpotent `N : (a,b) ↦ (0,a)`, `x₁` by `k • N`, and `xᵢ (i ≥ 2)` by `0`.
- **Genuine module.** Built the `B`-action as `Module.compHom` of an `AlgHom`
  `rep n k : zeroMulAlg n →ₐ[ℂ] End ℂ (Cyc n k)` obtained by `RingQuot.liftAlgHom` of
  `FreeAlgebra.lift` sending generator `i ↦ wt k i • N`. The `BRel` relations `ι i * ι j ↦ 0`
  hold because every product `(wt • N)(wt • N) = wt² • N² = 0`.
- **Indecomposable.** The socle vector `v = (0,1) = N u` lies in every nonzero submodule (apply
  `x₀ = N` to a non-socle vector, or the vector is already a socle multiple), so two nonzero
  complementary submodules would both contain `v`, contradicting `IsCompl`.
- **Pairwise nonisomorphic.** A `B`-linear equiv `φ : Mₖ ≃ Mₗ` is ℂ-linear (ℂ acts through
  `algebraMap ℂ B`) and intertwines the generator actions, forcing `(k−l)·φ v = 0`; since
  `φ v ≠ 0`, `k = l`.

## Key pattern discovered

Two distinct `Module (zeroMulAlg n) (Fin 2 → ℂ)` structures on the *same* underlying type make
`map_smul φ` unusable — typeclass resolution cannot disambiguate the two `SMul` instances (it
synthesizes one where the other is required). Fix: give each index its own carrier type
`def Cyc (n k : ℕ) : Type := Fin 2 → ℂ` with canonical (registered) instances. Then
`map_smul φ` works across the distinct types `Cyc n k` / `Cyc n l`, and `Submodule`/`IsIndecomposable`
resolve their module instance canonically (no `letI`/`show` juggling). `Module.compHom`'s
resulting `smul` is defeq to the underlying `rep` application, so `r • x = rep n k r x` by `rfl`.
