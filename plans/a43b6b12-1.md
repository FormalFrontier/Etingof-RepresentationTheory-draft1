## Current state

PR #2917 (commit `edbe14f`) introduced
`embed_t125_in_tree_per_kQ` as a new shared per-(F, Q) helper in
`Chapter6/FieldGenericT125.lean:71` (~386 lines), porting the
universal `embed_t125_in_tree`
(`Chapter6/InfiniteTypeConstructions.lean:4918-5279`). PR #2918
(commit `9847ad1`) then used the same helper at a second call
site (d₃-extends in `single_branch_leaf_both_extend_b2leaf_per_kQ`).
A third use is queued in PR #2911 once it is repaired.

The helper threads `F`, `Q`, `hOrient` through a 9-vertex T(1, 2, 5)
embedding into a tree with named structural distinctness inputs,
and dispatches to `t125_not_finite_type_per_kQ` via
`subgraph_infinite_type_transfer_per_kQ` and
`restrictOrientationViaEmb_isOrientationOf`. The universal version
is used four times inside
`Chapter6/InfiniteTypeConstructions.lean` (lines 7373, 7380, 7679,
7686), so even small structural drift in the per-(F, Q) port could
silently break multiple downstream call sites.

No review has been filed for this helper yet. It is a high-leverage
piece of new mathematics — substantial enough (~360 lines of
constructive embedding) to merit a dedicated fidelity audit before
more downstream code builds on it.
